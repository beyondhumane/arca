# Bounded adapter and extraction fuzzing

This is an executable, deterministic mutation harness, **not** a coverage-guided
libFuzzer target or proof of compatibility. It adds no fuzzing dependencies:
the isolated Cargo workspace uses the production adapter and its existing
`tempfile` dependency, with a lockfile seeded from the repository lockfile.
No official RAR tools are needed to run it.

On Linux, from the repository root:

```sh
cargo build --locked --manifest-path arca-rar/fuzz/Cargo.toml
python3 arca-rar/fuzz/run.py --runs 2000 --seed 140014 --seconds 300 --output /path/to/run-results
cargo clippy --locked --manifest-path arca-rar/fuzz/Cargo.toml --all-targets -- -D warnings
cargo fmt --manifest-path arca-rar/fuzz/Cargo.toml -- --check
```

`run.py` checks seed SHA-256 values, runs every valid seed through extraction,
then mutates the inner archive bytes or volume ordering. Operations include
bit flips, multi-byte flips, RAR5 header-CRC repair, truncation, omitted/duplicate
volumes, inserted bytes, naming schemes, first/last selected volumes, missing or
wrong passwords and cancellation. The stream SHA-256 fixes the ordered input
sequence on Python 3.12. It writes counts, budgets and baseline paths reached to
`report.json`, and preserves the first failure's exact input and process output.
Exit status 1 means a crash, timeout, invariant violation or baseline failure;
these are not silently classified as ordinary malformed archives.

The Rust process calls `open_with_progress`, `test`, `extract`, and successful
member previews. It checks no destination creation before publication on error,
an outside sentinel, containment, absence of output symlinks, exact output sizes
and preview/extraction agreement. It does **not** assert directory rollback after
publication begins. Production regression tests separately cover conflicts,
existing destination symlinks, aggregate budgets and publication I/O failure.

Budgets: 128 KiB input, up to four 32 KiB volume frames, 128 entries and 256 KiB
declared output per case. Open/test/extract cancel cooperatively after 250 ms.
Every case also has a fresh process with a 3 s wall timeout, 2 s CPU limit,
1 GiB address-space limit, 2 MiB per-file limit and disabled core dumps. Parent
wall budget defaults to 300 s, stopping before another case; the last case can
add at most 3 s. No VM-wide limits or filesystem fills are used. The report must
be checked for completed executions: a wall-limited partial campaign is not the
same as completing all requested mutations. Reproduce a saved case with:

```sh
python3 arca-rar/fuzz/run.py --runs 0 --seconds 30 --output /path/to/seed-check
# For a trusted, already minimized input (runner enforces the outer OS budgets):
arca-rar/fuzz/target/debug/arca-rar-bounded-fuzz /path/to/failure.case
```

## Corpus and license

`corpus/*.case` are generated by `python3 arca-rar/fuzz/make-seeds.py` from the
existing Arca-generated synthetic fixtures and the new independent RAR4/RAR5
matrix. They are licensed Apache-2.0 under the repository license, contain no
proprietary payload, and do not include upstream historical fixtures or tools.
`corpus/manifest.json` records source paths and seed hashes. Encoding: one mode
byte, one password-selector byte, then repeated little-endian u32 lengths and
unchanged archive bytes. Mode chooses modern/padded/legacy names, first/last
input, cancellation and conflict policy. Password selector maps to none,
`arca-test-only`, `password` or `wrong`.

The small corpus intentionally omits very large dictionaries/output, RAR7
revision-1 streams, historical codecs, long solid histories and real-world
files. Fuzzing does not exercise native UI or Windows/macOS filesystem behavior.
See [the validation record](../RAR_VALIDATION.md) for actual run evidence and gaps.
